# Проверка v0.3.2

`./gradlew :app:testDebugUnitTest :app:assembleRelease` — BUILD SUCCESSFUL, **44 теста, 0 ошибок** (5 новых).

## Причина

Загрузку выполнял только `OfflineSyncWorker` (WorkManager 2.9.1). Пока приложение открыто,
WorkManager запускает задачу сам (GreedyScheduler), но в его коде есть ограничение 90 минут
(`TimeLimiter`) и троттлинг после 5 попыток (`throttleIfNeeded`), после чего задача ждёт
системный JobScheduler. Для фонового приложения на Huawei он откладывается — до открытия
приложения, когда WorkManager снова запускает задачу. Это совпадает с поведением на часах;
точную причину остановки (`stopReason`) на часах я не видел — теперь она пишется в лог.

## Тесты

| Тест | Что проверяется |
|---|---|
| `drainsAllQueuedPlaylistsInOrder` | несколько плейлистов в очереди скачиваются по порядку |
| `offlineLeavesQueueForLater` | без сети очередь остаётся QUEUED, runner сообщает «есть работа» |
| `secondRunnerDoesNotDownloadTwiceAndServiceTakesOver` | второй runner не пишет параллельно; сервис ждёт, а когда система останавливает worker посреди трека, докачивает сам |
| `pauseStopsCurrentPlaylistKeepsFilesAndContinuesWithNext` | пауза останавливает текущий плейлист, скачанное остаётся, очередь переходит к следующему |
| `startsInForegroundImmediatelyAndStopsWhenQueueEmpty` | `DownloadService` сразу вызывает `startForeground` и сам останавливается при пустой очереди |

APK: `versionCode 6`, `0.3.2`, тот же сертификат `004322f9…eab9f2`; `DownloadService` — `dataSync`.
